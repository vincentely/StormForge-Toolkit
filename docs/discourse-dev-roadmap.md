# StormForge 论坛开发路线：上海二区试用与正式机迁移

2026-11-18 已开通腾讯云上海二区独立试用机。控制台显示标准型 S5.MEDIUM4（2 核 4 GB）、3 Mbps、独立公网 IP、Ubuntu Server 26.04 LTS 64 位、50 GB 通用型 SSD 系统盘（CLOUD_BSSD）。开发阶段计划运行一套团队可访问的 Discourse，官网和 StormForge Server 继续由原主机承载。控制台显示试用自 2026-11-18 19:39:39 起，至 **2026-12-18 19:39:39（北京时间）** 到期。正式机的规格和地域在迁移前根据试运行数据确认。

**试用部署回执。** 2026-11-18 已在独立试用机部署 Discourse 2026.11.0-latest.1。应用提交为 `2e02e9ce68a7be9b3646745cdcfb6786c225c6b5`，Docker 模板提交为 `c89cce3546b724878d7ab158bbd9478cf0a7b507`。云外预编译后交付的镜像归档为 1,436,931,072 字节，SHA-256 为 `9ba872ea781241f22948b2eb3fa98be1cd4900abfc2e4b323211b3a133af0de2`。核对了管理员登录、七个一级分类、四个标签组、主题与图片、容器重启及隔离恢复。试用入口经本机隧道访问，已接入 StormForge 开发账号服务。正式域名 HTTPS 和对外邮件待配置。

## 账户体系与登录验收

StormForge 负责用户注册、登录和账户状态，Discourse 保存帖子、版主权限和本地社区资料。试用机已关闭普通用户注册和邮件免密登录，当前的本地管理员仅用于部署和恢复。实际用户入口采用 DiscourseConnect，论坛以 StormForge 稳定的 `user_id` 作为 `external_id`。GitHub、微信等身份在 StormForge 内关联到同一用户时，应回到同一份论坛资料。

试用论坛已启用 DiscourseConnect。本次验收对应的 StormForge 账号服务提交为 `3a757ad6d349bbc4e7f4167d6de518134f74c89f`，开发构建通过了 5 项自动化测试。成员从论坛进入账号服务，选择微信扫码或 GitHub 授权。账号服务分别按本应用的微信 OpenID 或 GitHub 数字 ID 查询已绑定的活动账号，两条路径均以同一个 StormForge UUID 返回论坛。

微信不返回邮箱。试用模式为微信首次入坛的成员分配稳定的 `@wechat.forum.invalid` 专属地址，供论坛建档，该地址不能收信或找回账号。论坛关闭外发邮件，保留已有成员的主邮箱、昵称和角色。GitHub 继续使用已验证的主邮箱。迁移到正式机时需要确定真实联系邮箱的验证方式。

2026-11-18 已用同一个真实双绑定账号依次完成微信扫码和 GitHub 授权。两次回跳分别更新同一条论坛绑定，论坛用户 ID、创建时间和原主邮箱一致，成员仍为普通用户。仅绑定微信的新成员已通过隔离测试，覆盖活动账号查询、首次建档和再次进入；本轮只有一个双绑定真人账号，该场景尚无独立微信用户现场扫码记录。错误签名与重复 nonce 的检查已通过，微信和 GitHub 选择还验证了浏览器绑定、请求取消和单次消费。正式开放前另验收停用账号、退出与既有论坛会话撤销策略。

试用回调为 SSH 隧道的回环地址。迁移正式机时须配对目标环境的账号服务、正式论坛 HTTPS 回调和独立密钥。若同时更换开发身份库，先确认已有论坛成员在目标库中的 UUID 对应关系，再切换用户入口。[官方 DiscourseConnect 协议](https://meta.discourse.org/t/setup-discourseconnect-official-single-sign-on-for-discourse-sso/13045)

## 到期前迁到正式机

1. **12 月 11 日，准备正式机。** 在正式机装载与试用机相同的应用及插件版本，核对镜像和运行配置，准备数据库、上传卷、SMTP、所需应用密钥及论坛域名的有效证书。证书可通过 DNS 验证提前签发。在正式机配置团队访问限制。试用机当前用本地隧道验收，正式机须改为实际 HTTPS 站点地址、清除试用回环地址和自定义端口，并复核主题链接与图片。切换前至少提前一个原 DNS TTL 调低论坛记录的 TTL。
2. **12 月 13 日，预演恢复。** 将包含上传文件的近期备份恢复到隔离的目标论坛，暂时屏蔽外发邮件和通知。用本机域名解析覆盖直连新 IP，以真实域名验证 TLS、登录、角色、分类、帖子及附件。保留测试结果，并为最终恢复准备空目标。Discourse 站点备份中的插件数据需要配套的插件程序；SMTP、反向代理配置及相关密钥单独准备。
3. **建议 12 月 15 日切换，由负责人确认具体停写时段。** 旧站设为只读，暂停会修改数据的自动任务并处理待发队列；记录最后一帖、用户数和主题数。生成最终的数据库及附件备份，复制到机外并核对 SHA-256。在已隔离的正式机上恢复，并重查记录数、最后一帖、权限和原图。
4. **只切论坛域名。** 验收通过后把 `forum.vollagames.com` 的 A 记录切到新 IP；如已有 AAAA 记录，一并核实其去向。旧站继续只读并停发通知。用团队网络验证 HTTPS 确实命中新机，再在新机开启后台任务、发信和写入，以测试账号完成一帖、一图、一封邮件的验收。正式机沿用内测访问权限，公众开放按总方案另行验收。
5. **到期前收尾。** 至少经过原 DNS TTL，确认团队入口稳定、新机已成功生成第一份机外备份、恢复资料可取回。记录版本、备份位置、切换时间和下一次备份责任人，再处理试用机到期及续费设置。

**回退条件。** 新机开放写入前若恢复或验收失败，可将论坛解析指回旧机，确认新机停止任务后再恢复旧站写入。新机已有新帖或上传时，先冻结新机写入并生成机外备份，以新机最新数据修复或恢复到回退目标，核对新增内容后才切回。若到期前来不及完成切换，提前完成停写后的机外备份并验证可恢复；如需保持试用站连续可用，由负责人在到期前确认续费。
